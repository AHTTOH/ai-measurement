## 처음 한 번

```powershell
npm install
npx playwright install chromium firefox webkit   # E2E 테스트용(Edge는 설치된 Microsoft Edge를 쓴다)
Copy-Item infra/.env.example .env      # 값을 채운다(비밀번호 등). AI_PROVIDER=mock, GRADING_LLM_PROVIDER=mock
```

`.env`의 DB 비밀번호는 아래처럼 만들어 넣으면 형식 규칙(영문·숫자·_·- 16자 이상)을 지킨다.

```powershell
node -e "console.log(require('crypto').randomBytes(24).toString('base64url'))"
```

## DB (2026-09-27부터 Supabase)

`.env`는 Supabase 프로젝트 `ai-test`에 붙어 있다(결정 D17). 마이그레이션·로그인 계정·운영자 계정은 이미 적용했으므로 아래 1·2단계는 건너뛰고 3단계부터 하면 된다. 스키마를 바꿨을 때만 `npm run db:migrate`를 다시 돌린다.
오프라인으로 개발하려면 `.env`의 DB 항목을 로컬 값(`DATABASE_HOST=127.0.0.1`, `DATABASE_PORT=55432`, `DATABASE_NAME=ai_measurement`, `DATABASE_SSL=disable`, `DATABASE_POOLER_PROJECT_REF` 줄 삭제, `MIGRATION_DB_USER=postgres`)으로 바꾸고 1단계부터 한다.
자동 테스트는 DB 설정과 상관없이 항상 임베디드 PostgreSQL을 스스로 띄운다.

## 실행 순서 (터미널 5개)

```powershell
# 1. 개발 DB (창을 열어 둔다)
npm run db:dev

# 2. 마이그레이션, 역할별 DB 로그인, 운영자 계정(처음 한 번. 로그인 비밀번호를 바꾸면 db:logins만 다시)
npm run db:migrate
npm run db:logins
$env:NEW_ADMIN_PASSWORD='12자 이상 비밀번호'; npm run admin:create -- --username operator

# 3. 웹 빌드(수험생·관리자 두 벌) 후 수험생 서버
npm run build:web
npm run start:candidate-server    # 코드 수정을 바로 반영하려면 npm run dev:candidate-server

# 4. 관리자 서버
npm run start:admin-server        # 또는 npm run dev:admin-server

# 5. 채점 워커
npm run start:worker
```

| 화면 | 주소 | 제공 서버 |
|---|---|---|
| 응시 화면 | http://localhost:3000/ | 수험생 서버 |
| 운영 화면 | http://localhost:3001/admin | 관리자 서버(127.0.0.1에서만 열림) |

화면 코드를 고치며 볼 때는 Vite 개발 서버를 쓴다. 각자 자기 API만 해당 서버로 넘긴다.

| 명령 | 넘기는 API | 대상(.env) |
|---|---|---|
| `npm run dev:web:candidate` | `/api/candidate` | `WEB_DEV_CANDIDATE_API_ORIGIN` |
| `npm run dev:web:admin` | `/api/admin` | `WEB_DEV_ADMIN_API_ORIGIN` |

두 개발 서버를 함께 띄우면 두 번째가 다른 포트를 잡는다. 터미널에 찍힌 주소로 연다.

## 운영 화면에서 시험 한 번 돌려 보기

1. 운영 화면 → 시험 패키지 등록에서 `sample-ai-practice` 등록
2. 시험 상세 → 시험 열기 → 응시자 발급(접두사, 인원) → PIN CSV 내려받기
3. 응시 화면에서 응시번호·PIN으로 로그인해 응시
4. 시험 상세 → 채점 실행(즉시) → 결과 표와 응시 상세 확인

## 검증 명령

| 명령 | 내용 |
|---|---|
| `npm run typecheck` | 전 패키지 타입 검사 |
| `npm test` | 단위 테스트 |
| `npm run test:integration` | 통합 테스트(임베디드 PostgreSQL을 스스로 띄우고 역할별 로그인으로 접속한다) |
| `npm run test:e2e` | 웹 빌드 후 브라우저 E2E. 전체 흐름(Chromium)과 브라우저별 점검(Chromium·Firefox·WebKit·Edge: 핵심 동작, axe 접근성, 320·768·1024px 가로 넘침) |
| `npm run test:coverage` | 단위 + 통합 커버리지 |
| `npx tsx tests/load/run-load-test.ts 120 180 1 burst` | 120명 3분 과부하 시험. 셋째 값은 수험생 서버 대수(2 이상이면 라운드로빈 프록시 뒤) |
| `npx tsx tests/load/run-load-test.ts 120 7080 1 rehearsal` | 120명 118분 자동 리허설(실제 시험처럼 20~60초마다 행동, 끝나면 채점까지) |
| `npm run db:generate -- <이름>` | 스키마 변경 후 마이그레이션 생성. 변경이 없으면 "No schema changes"가 나온다 |

새 테이블을 만들면 `infra/db/migrations/0001_access-roles.sql`과 같은 방식으로 역할별 권한을 주는 마이그레이션을 함께 만든다. 권한을 주지 않으면 서버가 그 테이블을 읽지 못한다(의도한 동작). 권한 표는 `docs/decisions/2026-09-27-권한-구조-분리.md`.
