# 모의고사 리허설 절차 (사람 참여)

> 최초 작성: 2026-09-27 · 마지막 갱신: 2026-09-27
> 대상: 실제 시험 전에 운영자와 참가자(응시자 역할)가 함께 한 번 끝까지 치러 보는 사람. 자동 리허설(가상 응시자)로 확인할 수 없는 것, 즉 화면 이해도, 안내문, 장애 대응 손발, 채점 결과의 타당성을 확인한다.
> 함께 볼 문서: `docs/runbook/시험-운영-절차.md`(운영), `docs/runbook/API-키-연동-절차.md`(실제 AI 연동), `docs/audit/2026-09-27-부하-테스트-다중-인스턴스.md`(자동 리허설 결과)

## 1. 목표와 합격 기준

| 확인할 것 | 합격 기준 |
|---|---|
| 참가자가 도움 없이 로그인부터 제출까지 할 수 있다 | 운영자 개입 없이 끝낸 참가자가 전원. 막힌 곳은 모두 기록 |
| 남은 시간·남은 토큰 표시가 이해된다 | 사후 설문에서 "헷갈렸다"가 없거나 원인이 기록됨 |
| 진행 중 조건 변경(공지)이 눈에 띈다 | 참가자 전원이 공지를 확인함(감사 로그의 notice_shown·확인 기록) |
| 장애 대응 절차가 손에 익는다 | 아래 3장의 시나리오를 운영자가 절차서대로 처리 |
| 채점 결과가 납득된다 | 채점 뒤 운영자와 출제자가 표본 3명의 도달 과정과 점수를 보고 이견을 기록 |

## 2. 준비 (리허설 3일 전까지)

1. 리허설 전용 시험 패키지를 준비한다. slug를 실제 시험과 다르게 둔다(열린 시험은 다시 등록할 수 없다).
2. `npm run exam:validate -- exams/<slug>`로 검증한다. 문제 0건.
3. 서버 구성은 실제 시험과 같게 둔다. 수험생 서버, 관리자 서버, 채점 워커를 각자 계정으로 띄운다(`docs/runbook/시험-운영-절차.md`의 '프로세스 구성').
4. 실제 AI로 할지 모의 AI로 할지 정한다. 실제 AI면 API 키 연동 절차를 먼저 끝낸다. 모의 AI면 화면에 '모의 AI'가 뜬다는 것을 참가자에게 미리 알린다.
5. 참가자 계정을 발급하고 PIN CSV를 내려받는다. 참가자 수는 3명 이상, 가능하면 실제 시험장 PC와 네트워크를 쓴다.
6. 역할을 정한다.

| 역할 | 할 일 |
|---|---|
| 운영자 | 운영 PC에서 관리자 화면 조작, 장애 시나리오 처리 |
| 감독관 | 참가자 질문 응대, 막힌 곳 기록(개입하면 개입 시각과 내용을 적는다) |
| 기록자 | 타임라인 기록(아래 5장 양식), 화면 캡처 |
| 참가자 | 실제 응시자처럼 푼다. 떠오르는 불편을 그때그때 메모 |

## 3. 진행 중에 일부러 일으킬 장애 시나리오

리허설 도중 운영자가 정해 둔 시각에 하나씩 일으키고, `docs/runbook/시험-운영-절차.md`의 '장애 대응'대로 처리한다.

| 시각(시작 후) | 시나리오 | 하는 방법 | 확인할 것 |
|---|---|---|---|
| 15분 | 응시자 브라우저 새로고침 | 참가자 1명이 AI 응답 중에 새로고침 | 답하던 응답이 이어서 보이고, 답안이 남아 있다 |
| 30분 | 다른 PC에서 다시 로그인 | 참가자 1명이 다른 PC로 로그인 | 이전 PC는 로그인이 끊기고, 새 PC에서 이어서 푼다 |
| 45분 | 네트워크 끊김 | 참가자 1명의 네트워크를 2분 끊었다 연결 | 다시 연결되면 이어서 쓰고, 운영자가 시간 연장(사유 기록) |
| 60분 | 수험생 서버 재시작 | 운영자가 수험생 서버를 멈췄다 다시 띄움 | 저장된 대화·답안이 그대로이고, 재시작 순간 끊긴 AI 응답은 토큰 환불 |
| 75분 | 토큰 환불 | 응시 상세 → 토큰 원장에서 전송 1건 환불(사유 필수) | 참가자 화면의 남은 토큰이 늘어난다 |
| 90분 | 로그인 잠금 | 참가자 1명이 PIN을 5번 틀림 | 잠금 안내가 뜨고, 잠금 시간 뒤 풀린다 |

수험생 서버를 두 대 이상 운영하는 경우에는 60분 시나리오를 한 대만 멈추는 것으로 바꾼다. 멈춘 서버가 맡던 응답은 사라지고, 다른 서버로 접속한 참가자는 계속 푼다(결정: `docs/decisions/2026-09-27-수험생-서버-다중-인스턴스.md`).

## 4. 끝난 뒤

1. 모든 참가자가 제출했거나 시간이 끝났는지 확인한다.
2. 채점 실행(즉시). 끝날 때까지 걸린 시간을 적는다.
3. 표본 3명(잘한 사람, 보통, 못한 사람)의 응시 상세를 운영자와 출제자가 함께 본다. 항목별 점수와 근거 인용이 납득되는지 적는다.
4. 점수 CSV와 응시자별 전체 기록을 내려받아 리허설 기록과 함께 보관한다.
5. 참가자 설문(아래 6장)을 받는다.
6. 결과를 `docs/audit/YYYY-MM-DD-모의고사-리허설.md`로 남긴다. 발견한 문제는 모두 닫은 뒤 실제 시험을 연다.

## 5. 타임라인 기록 양식

| 시각 | 누가 | 무엇을 | 화면·로그 | 조치 | 걸린 시간 |
|---|---|---|---|---|---|
| 예: 10:15 | 참가자 B | AI 응답 중 새로고침 | 응답이 이어서 보임 | 없음 | 0분 |

## 6. 참가자 설문 (5분)

1. 로그인부터 시작까지 막힌 곳이 있었나요? 어디였나요?
2. 남은 시간과 남은 토큰 표시를 바로 이해했나요?
3. 자료 첨부(열·행 고르기)는 어렵지 않았나요?
4. 진행 중 공지를 언제 알아챘나요? 놓칠 뻔했나요?
5. 답안이 저장되었는지 믿을 수 있었나요?
6. 그 밖에 불편했던 점

## 7. 자동 리허설과의 관계

가상 응시자 120명이 120분 동안 실제 시험처럼 행동하는 자동 리허설은 서버·DB가 버티는지를 본다(`npx tsx tests/load/run-load-test.ts 120 7080 1 rehearsal`). 사람 참여 리허설은 그것이 볼 수 없는 화면 이해도와 운영 손발을 본다. 둘 다 통과해야 실제 시험을 연다.
