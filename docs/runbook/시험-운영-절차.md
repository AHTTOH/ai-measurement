# 시험 운영 절차

> 최초 작성: 2026-09-27 · 마지막 갱신: 2026-09-27 (권한 구조 분리, 수험생 서버 다중 인스턴스, 모의고사 리허설 절차 연결)
> 대상: 시험 운영자. 시험 전·당일·종료 후에 할 일과 장애 대응.

## 시험 1주 전

사람이 참여하는 모의고사 리허설은 `docs/runbook/모의고사-리허설-절차.md`를 따른다.

1. **시험 패키지 검증**: `npm run exam:validate -- exams/<slug>`. 문제가 0건이어야 한다. 탐지 정규식은 ReDoS 검사를 통과해야 한다.
2. **자료 점검**: 자료 속 개인정보는 전부 가공 데이터인지 확인한다. 실존 인물 데이터가 Claude API로 나가면 안 된다.
3. **등록과 리허설**: 운영 화면에서 등록 → 시험 열기 → 운영자가 응시자 계정 2~3개로 끝까지 풀어 본다 → 채점 → 결과 확인. 리허설 시험은 slug를 따로 둔다(열린 시험은 다시 등록할 수 없다).
4. **Claude API 확인**: `docs/runbook/API-키-연동-절차.md`의 확인 항목(티어, 레이트 리밋, 캐시 적중)을 끝낸다.
5. **응시자 발급**: 시험 상세 → 응시자 발급. PIN은 발급 화면에서 한 번만 보이므로 CSV를 바로 내려받아 보관·배포한다.

## 프로세스 구성 (권한 구조 분리, 2026-09-27)

| 프로세스 | 실행 | 여는 곳 | DB 로그인 |
|---|---|---|---|
| 수험생 서버 | `npm run start:candidate-server` | 시험장 네트워크(`CANDIDATE_SERVER_HOST=0.0.0.0`, 포트 3000) | `CANDIDATE_SERVER_DB_USER` |
| 관리자 서버 | `npm run start:admin-server` | 운영 PC만(`ADMIN_SERVER_HOST=127.0.0.1`, 포트 3001) | `ADMIN_SERVER_DB_USER` |
| 채점 워커 | `npm run start:worker` | 열지 않음 | `GRADING_WORKER_DB_USER` |
| 관리 스크립트 | `db:migrate`, `db:logins`, `admin:create` | 운영자가 직접 실행 | `MIGRATION_DB_USER`(스키마 소유자) |

- 시험장 방화벽·공유기에는 수험생 서버 포트만 연다. 관리자 서버 포트는 시험장에서 닿으면 안 된다.
- 권한 표와 이유: `docs/decisions/2026-09-27-권한-구조-분리.md`.
- DB는 Supabase(결정 D17). 무료 플랜 DB 연결 한도가 60이므로 수험생 서버를 늘리면 `*_DB_MAX_CONNECTIONS` 합이 약 45를 넘지 않게 한다. Data API로 `public`이 노출되지 않는지 시험 전에 확인한다.

### 프로세스별 환경 파일

로컬 개발은 `.env` 하나를 모두 읽지만, 운영에서는 프로세스마다 필요한 항목만 담은 파일을 따로 둔다. 다른 프로세스의 DB 비밀번호와 소유자 비밀번호가 섞이지 않게 하기 위해서다.

| 파일(예) | 담는 항목 |
|---|---|
| `candidate.env` | DB 공통, `CANDIDATE_SERVER_*`, `EXAMS_DIR`, 로그인 정책, `AI_PROVIDER`, `ANTHROPIC_API_KEY`, `CANDIDATE_AI_REQUESTS_PER_MINUTE`, `SESSION_SWEEP_SECONDS`, `CANDIDATE_WEB_DIST_DIR` |
| `admin.env` | DB 공통, `ADMIN_SERVER_*`, `EXAMS_DIR`, 로그인 정책, `GRADING_LLM_PROVIDER`, `UPLOAD_MAX_MB`, `ADMIN_WEB_DIST_DIR` |
| `worker.env` | DB 공통, `GRADING_WORKER_*`, `EXAMS_DIR`, `GRADING_LLM_PROVIDER`, `ANTHROPIC_API_KEY`, `GRADING_*` |
| `owner.env` | DB 공통, `MIGRATION_DB_*`, 세 로그인의 `*_DB_USER`, `*_DB_PASSWORD`(db:logins용). 운영자만 읽을 수 있게 둔다 |

실행 예: `npx tsx --env-file=candidate.env server/src/candidate-main.ts`. 항목이 빠지면 프로세스가 빠진 이름을 모두 적고 기동을 거부한다.

## 서버 설정 점검

| 항목 | 기준 |
|---|---|
| `AI_PROVIDER`, `GRADING_LLM_PROVIDER` | `anthropic`. `mock`이면 화면에 '모의 AI'·'모의 채점'이 뜬다 |
| `COOKIE_SECURE` | HTTPS로 운영하면 `true` |
| `LOGIN_ATTEMPTS_PER_IP_PER_MINUTE` | 시험장이 한 IP(공유기·프록시)로 들어오면 응시 인원의 몇 배. 기본 예시 600. 수험생 서버마다 따로 센다(서버 CPU 보호용) |
| `CANDIDATE_AI_REQUESTS_PER_MINUTE` | 응시자 1명의 분당 AI 요청 상한. 예시 20 |
| 인스턴스 수 | 수험생 서버는 여러 대를 로드밸런서(세션 고정 불필요) 뒤에 둘 수 있다. 한 PC면 1대가 낫다(코어를 나눠 써서 2대가 더 느리다). 관리자 서버는 한 대. 근거: `docs/decisions/2026-09-27-수험생-서버-다중-인스턴스.md` |
| 리버스 프록시 | 프록시 뒤에서는 모든 요청이 프록시 IP로 보이므로 IP별 로그인 한도가 전체 한도가 된다. 위 값을 넉넉히 둔다 |
| 동시 로그인 속도 | 120명이 같은 순간에 로그인하면 해시 계산이 몰려 로그인·응시 시작이 2~3초 걸린다(2026-09-27 부하 테스트, 노트북 1대). 입장을 조별로 나누면 줄어든다. 수험생 서버 환경변수 `UV_THREADPOOL_SIZE=8`도 도움이 된다 |

## 시험 당일

1. 수험생 서버·관리자 서버·워커 기동, 운영 PC에서 운영 화면(`http://127.0.0.1:3001/admin`) 로그인
2. 시험 상세 → **시험 열기**. 응시자는 안내문과 서약을 확인한 뒤 각자 시작한다. 시간은 각자 시작 시각부터 120분이다
3. 진행 중 확인: 시험 상세의 응시 현황(시작 전·응시 중·제출·시간 종료, 사용 토큰)
4. 모든 응시자가 시작한 뒤 **시험 종료**를 누르면 새로 시작할 수 없다. 이미 시작한 응시자는 자기 시간까지 계속한다

## 장애 대응

| 상황 | 조치 |
|---|---|
| 응시자 PC·네트워크 문제로 시간 손실 | 응시 상세 → 시간 연장(분, 사유). 감사 로그에 남는다 |
| AI 응답 실패(레이트 리밋·장애)로 토큰만 차감 | 응시 상세 → 토큰 원장 → 해당 전송 행 '환불'(사유 필수). 같은 메시지는 한 번만 환불된다 |
| 응시자가 다른 곳에서 다시 로그인 | 이전 로그인은 자동으로 끊긴다. 응시 기록은 그대로다 |
| 로그인 잠김(실패 5회) | 15분 뒤 풀린다(`LOGIN_LOCK_MINUTES`). PIN을 다시 확인해 준다 |
| 서버 재시작 | 저장된 대화·답안·원장은 유지된다. 재시작 순간 생성 중이던 AI 응답은 사라지므로 해당 전송은 환불한다. 수험생 서버가 여러 대면 죽은 서버가 맡던 대화는 20초 뒤 다시 보낼 수 있다 |

## 종료 후

1. 모든 응시자가 제출했거나 시간이 끝났는지 확인한다(응시 중이면 채점에서 빠진다)
2. 시험 상세 → **채점 실행**. 배치(비용 50%, 결과까지 최대 24시간) 또는 즉시
3. 채점 작업이 '완료'가 되면 결과 표 확인. 메모에 LLM 실패 건수가 있으면 해당 항목은 미채점이며 총점이 비어 있다. 다시 채점을 실행한다
4. 중대 보안 위반이 있는 응시자는 시험의 위반 처리 기준(`violationPolicy`)에 따라 판정이 표시된다. 응시 상세의 위반 목록과 대화에서 근거를 확인한다
5. 점수 CSV와 응시자별 전체 기록 JSON을 내려받아 보관한다
