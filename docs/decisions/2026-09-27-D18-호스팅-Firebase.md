## Firebase Hosting 때문에 바꾼 것

| 제약(2026-09-27 실제 확인) | 조치 |
|---|---|
| Hosting은 Cloud Run으로 `__session` 쿠키만 넘긴다 | 로그인 쿠키 이름을 설정으로 뺐다. 배포에서는 두 서버 모두 `__session`(도메인이 달라 섞이지 않는다). 로컬은 `aim_candidate`/`aim_admin` |
| Hosting을 거치면 Host 헤더가 Cloud Run 주소가 된다 | 같은 출처 검사가 볼 헤더를 설정으로 뺐다. 배포에서는 `x-forwarded-host` |
| Hosting은 SSE 응답을 끝까지 모아 한꺼번에 보낸다(조각 5개가 같은 시각에 도착) | 화면은 SSE 대신 `/progress`를 0.5초마다 읽는다. 짧은 요청이라 Hosting의 60초 제한에도 걸리지 않는다. SSE 경로는 API·부하 테스트용으로 남겼다 |
| Supabase 무료 풀러는 계정당 동시 연결 15개 | 수험생 서버를 1대·연결 6개로 둔다. 배포 중 옛 버전과 새 버전이 겹쳐도 14개. 코드는 여러 대를 지원한다 |
| Cloud Run 서비스는 포트를 열어야 뜬다 | 채점 워커에 선택적 상태 확인 포트(`GRADING_WORKER_HEALTH_PORT`) |

## 배포 중 발견해 고친 결함

- `.gitignore`의 `exams/*`가 루트 기준이 아니라서 `server/src/modules/exams/` 소스까지 무시해, 빌드 업로드에서 빠졌다. `/exams/*`로 고쳤다.

## 확인 (2026-09-27, Hosting 주소 경유)

관리자 로그인(`__session` 쿠키), 시험 목록, 응시자 발급, 응시자 로그인, 응시 시작, 실제 Claude 응답 1회(전송 1.1초, 진행 텍스트가 늘어나다 3.2초에 완료) 모두 정상.

## 남은 위험

- 관리자 웹이 인터넷에 열려 있다. 비밀번호와 잠금으로만 막는다. 필요하면 Cloud Run 관리자 서비스에 IAP를 붙인다.
- 수험생 서버와 채점 워커를 상시 켜 두므로 사용하지 않아도 요금이 나온다. 시험이 없는 기간에는 최소 대수를 0으로 내릴 수 있다(`docs/runbook/배포-절차.md`).
- 로컬 `.env`도 같은 Supabase를 쓰므로 로컬 개발이 운영 DB에 쓴다. 로컬 연결 수는 줄여 두었다(수험생 4, 관리자 2, 워커 2).
