# 결정: 권한 구조 분리 (관리자 / 수험생)

> 결정일: 2026-09-27 · 결정자: 신영환 · 기록: Claude (Opus 5.5 세션)
> 근거: 2026-09-27 신영환 지시 "권한구조 나눠서 관리자/수험생 2개로 나눠서 작업해줘".
> 범위: 기존 최상위 폴더(server, web, infra, grading, scripts, tests) 안에서만 나눈다. `admin/`, `candidate/` 같은 새 최상위 폴더는 만들지 않았다. 필요하면 먼저 허락을 받는다.

## 결정

수험생 쪽과 관리자 쪽을 세 겹으로 나눈다. 한 겹이 뚫려도 다음 겹이 막는다.

| 겹 | 수험생 | 관리자 | 채점 워커 |
|---|---|---|---|
| 프로세스 | `server/src/candidate-main.ts` | `server/src/admin-main.ts` | `grading/src/worker-main.ts` |
| API | `/api/candidate/*`만 있음 | `/api/admin/*`만 있음 | 없음(HTTP 안 엶) |
| 웹 빌드 | `web/dist/candidate` (`web/index.html`) | `web/dist/admin` (`web/admin.html`) | 없음 |
| 기본 포트·주소 | 3000, 0.0.0.0(시험장 PC 접속) | 3001, 127.0.0.1(운영 PC만) | 없음 |
| DB 역할 | `aim_candidate_server` | `aim_admin_server` | `aim_grading_worker` |
| DB 로그인 | `CANDIDATE_SERVER_DB_USER` | `ADMIN_SERVER_DB_USER` | `GRADING_WORKER_DB_USER` |
| 쿠키 | `aim_candidate` | `aim_admin` | 없음 |

마이그레이션·운영자 계정 생성·DB 로그인 적용은 스키마 소유자 계정(`MIGRATION_DB_USER`)으로 관리 스크립트만 한다. 서버·워커에는 소유자 계정을 주지 않는다.

## DB 권한 (infra/db/migrations/0001_access-roles.sql)

원칙은 두 가지다. 필요한 것만 준다. 대화·토큰 원장·답안·감사 로그는 어느 역할도 UPDATE·DELETE·TRUNCATE할 수 없다(추가만).

| 테이블·컬럼 | 수험생 서버 | 관리자 서버 | 채점 워커 |
|---|---|---|---|
| exams (루브릭·정답 제외 컬럼) | 읽기 | 읽기·쓰기 | 읽기 |
| exams.rubrics, exams.answer_keys | 불가 | 쓰기만(등록), 읽기 불가 | 읽기 |
| admins | 불가 | 읽기 | 불가 |
| candidates | 읽기 | pin_hash 제외 읽기, 추가 | pin_hash 제외 읽기 |
| auth_sessions | 읽기·추가·폐기 컬럼 수정 | 읽기·추가·폐기 컬럼 수정 | 불가 |
| exam_sessions | 읽기·추가, status·ended_at 수정 | 읽기, expires_at 수정(시간 연장) | 읽기 |
| conversations | 읽기·추가, status·closed_at 수정 | 읽기 | 읽기 |
| messages, answers | 읽기·추가 | 읽기 | 읽기 |
| attachments, attachment_blobs | 읽기·추가 | attachments 읽기 | attachments 읽기 |
| token_ledger | 읽기·추가(차감) | 읽기·추가(환불) | 불가 |
| audit_events | 읽기·추가 | 읽기·추가 | 불가 |
| client_events | 추가만 | 읽기 | 불가 |
| grading_jobs | 불가 | 읽기·추가 | 읽기·수정(상태·진행률·잠금·배치 정보·오류) |
| grade_items, session_scores, violations | 불가 | 읽기 | 읽기·추가·삭제(재채점) |

이 표가 막는 대표 사고:

- 수험생 서버가 뚫려도 루브릭·정답·운영자 비밀번호 해시·채점 결과를 읽을 수 없다.
- 관리자 서버나 채점 워커가 뚫려도 응시자 PIN 해시를 읽을 수 없다(0002_candidate-pin-privacy.sql, 2026-09-27 보안 검토에서 추가).
- 수험생 서버가 뚫려도 시험 종료 시각을 늘리거나 시험 상태를 바꿀 수 없다.
- 관리자 서버가 뚫려도 수험생 대신 답안·대화를 쓰거나, 기록을 고치거나 지울 수 없다.
- 채점 워커가 뚫려도 토큰 원장·응시 기록을 쓸 수 없다.

권한 테스트: `tests/integration/access-roles.test.ts`. 역할별로 거부돼야 할 쿼리가 PostgreSQL 권한 오류(42501)로 막히는지 확인한다.

## 코드에서 바뀐 점

- **설정:** `server/src/config/candidate-server-config.ts`, `admin-server-config.ts`. 수험생 서버는 AI 키를 받고 업로드 한도를 받지 않는다. 관리자 서버는 AI 키를 받지 않는다. 공통 로그인 정책은 `common-config.ts`.
- **서비스 조립:** `candidate-services.ts`, `admin-services.ts`. 각 서버는 자기 쪽 서비스만 만든다. 시간 연장은 관리자 모듈의 `SessionExtensionService`로 옮겼다.
- **인증:** 로그인 세션 저장소(`auth-session-store.ts`)는 같이 쓰고, 수험생 로그인(`candidate-auth-service.ts`)과 관리자 로그인(`admin-auth-service.ts`)은 따로 있다.
- **시험 조회:** 두 서버 모두 `exam-columns.ts`의 컬럼 목록으로만 시험을 읽는다. 전체 컬럼(`select()`)으로 읽으면 권한 오류가 난다.
- **캐시:** 서버마다 시험 캐시가 따로 있으므로 시험 상태(열기·종료)는 매번 DB에서 읽는다. 큰 컬럼은 패키지 해시·등록 시각이 같을 때만 캐시를 쓴다. 관리자가 시험을 열면 수험생 서버가 재시작 없이 반영한다(테스트 있음).
- **관리자 화면의 응시 AI 표시:** 관리자 서버는 수험생 서버 설정을 모르므로, 이 시험의 AI 응답 메시지에 기록된 공급자를 보여 준다(`aiProvidersUsed`).
- **웹:** `vite build --mode candidate`, `--mode admin`으로 따로 빌드한다. 수험생 번들에 관리자 API 경로가 없고, 관리자 번들에 응시 API 경로가 없음을 빌드 결과에서 확인했다.

## 운영에서 지킬 것

- 프로세스마다 필요한 환경변수만 담은 파일을 따로 둔다. 로컬 개발은 편의상 `.env` 하나를 모두 읽는다.
- 관리자 서버는 운영 PC에서만 닿게 둔다(`ADMIN_SERVER_HOST=127.0.0.1`). 시험장 네트워크에는 수험생 서버 포트만 연다.
- 새 DB 로그인 비밀번호는 `npm run db:logins`로 적용한다. 여러 번 실행해도 결과가 같다.
