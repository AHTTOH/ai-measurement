# 웹 화면 설계 (응시자·관리자)

> 최초 작성: 2026-09-27 · 마지막 갱신: 2026-09-27
> 근거: `docs/PRD.md` 2·6·7·8·9·11장, 구현계획 4·6장, 전역 디자인 규칙(`~/.claude/rules/ecc/web/design-quality.md`)의 2-pass 절차

## 브리프 요약

- **응시자 화면**: 120분 동안 실무 과제 3개를 푸는 작업대다. 문항·답안·자료·AI 대화를 한 화면에서 오가야 한다. 시간과 토큰은 줄어드는 자원이고, 중간에 공지가 끼어든다.
- **관리자 화면**: 시험 등록·운영과 결과 확인. PRD 8장대로 3축 점수를 단순하게 보여주고, 응시자 한 명이 어떻게 결과에 도달했는지 추적할 수 있어야 한다.
- 쓰는 사람: 업무 역량 평가를 받는 직장인과 시험 운영자. 장식보다 판독성이 중요하다.

## 1 pass: 토큰 계획

| 축 | 계획 |
|---|---|
| Color | 흰 배경, 진한 글자, 파란 강조 하나, 회색 테두리 카드 |
| Type | Pretendard 한 가지, 굵기로 위계 |
| Layout | 좌측 문항 목록, 가운데 문항·답안, 우측 AI 대화의 3단. 관리자는 사이드바 + 표 |
| Principles | 깔끔하고 방해 없는 시험 화면 |

## 2 pass: 브리프 대조와 수정 내역

| 1 pass 선택 | 판정 | 바꾼 것과 이유 |
|---|---|---|
| 흰 배경 + 파란 강조 하나 + 회색 카드 | 기본값(회색 위 단일 강조, SaaS 카드 키트) | 색을 **자원 상태의 의미**로만 쓴다. 남은 시간·남은 토큰은 여유(청록) → 주의(호박) → 위험(적)으로 변한다. 중대 위반은 적색, 공지는 호박색 좌측 띠. 강조색은 행동(버튼·포커스) 하나에만 쓴다 |
| 카드로 모든 영역을 자르기 | 기본값 | 카드 대신 **구획선과 간격 리듬**으로 영역을 나눈다. 둥근 모서리는 입력·버튼에만 작게 쓰고 패널에는 쓰지 않는다 |
| 상단은 평범한 흰 헤더 | 브리프를 놓침 | 상단을 **계기판**으로 만든다. 짙은 청회색 띠 위에 남은 시간과 토큰 게이지를 크게 둔다. 화면에서 대담함을 쓰는 곳은 여기 한 곳뿐이다 |
| 3단 레이아웃 | 브리프에 맞음(유지) | IDE처럼 문항·답안·AI를 동시에 봐야 하므로 유지. 단 AI 대화 칸은 옅은 청색 면으로 구분해 "AI가 만든 글"이 한눈에 다르게 보이게 한다 |
| 관리자 사이드바 + 카드 대시보드 | 기본값(대시보드 공식) | 사이드바를 없애고 **표가 주인공**인 화면으로. 3축 점수는 숫자 옆에 가는 막대를 같이 그려 표 안에서 비교되게 한다(차트를 따로 두지 않는다) |
| Pretendard 한 가지 | 브리프에 맞음(유지) | 한국어 판독성이 가장 좋은 서체이고 로컬 번들로 시험장 네트워크에 의존하지 않는다. 숫자는 tabular-nums로 자리를 고정한다. 모노스페이스는 쓰지 않는다 |

## 확정 토큰

| 이름 | 값 | 쓰임 |
|---|---|---|
| `--ink` | `#17212B` | 본문 글자 |
| `--ink-muted` | `#5B6875` | 보조 글자 |
| `--paper` | `#FFFFFF` | 기본 면 |
| `--paper-sunken` | `#F3F5F7` | 입력 영역, 표 머리 |
| `--rule` | `#DDE2E7` | 구획선 |
| `--console` | `#1F2F3D` | 상단 계기판 |
| `--ai-surface` | `#EEF4FA` | AI 응답 면 |
| `--action` | `#1D5FBF` | 버튼·링크·포커스 |
| `--ok` | `#0F7C74` | 자원 여유 |
| `--caution` | `#B7791F` | 자원 주의, 공지 |
| `--danger` | `#C0392B` | 자원 위험, 중대 위반 |

- 글자 크기: 계기판 수치 28px/700, 문항 제목 20px/700, 본문 15px/400, 보조 13px.
- 간격: 4px 배수. 패널 안쪽 20px, 구획 사이 24px.
- 모서리: 입력·버튼 6px. 패널·표는 0.

## 와이어프레임

응시자(좌측 정렬, 데스크톱 기준. 1024px 미만에서는 AI 칸이 아래로 내려간다):

```
┌ 계기판 ───────────────────────────────────────────────────────────────┐
│ 샘플 AI 실무역량 평가  T0001   [직원 데이터][고객 VOC][출장비]   토큰 ▰▰▰▱ 22,180  남은 시간 01:23:45 │
├──────────────┬──────────────────────────────────┬───────────────────┤
│ 과제 설명 ▸   │ 1-3  AI 활용 분석                 │ AI 대화 (대화 1)   │
│ 하위문항      │ 지시문                            │  응시자 메시지      │
│  1-1 제출됨   │ ┌ 답안 ─────────────────────┐    │  AI 응답(청색 면)   │
│  1-2 작성 중  │ │                            │    │                   │
│  1-3          │ └────────────────────────────┘    │ 첨부 칩            │
│ 자료          │ 저장됨 12:03  [최종 제출]          │ [입력창]  [보내기]  │
│  직원 명부     │                                   │ 이번 전송 차감 표시 │
└──────────────┴──────────────────────────────────┴───────────────────┘
공지는 계기판 바로 아래에 호박색 띠로 나타나고, 읽음 처리 전까지 남는다.
```

관리자:

```
시험 목록 ─ 표(시험명, 상태, 응시자, 진행/제출/만료) + 패키지 등록 영역
시험 상세 ─ 상태 전환, 응시자 발급, 채점 실행 ─ 결과 표(응시번호, 상태, 사용 토큰, 총점, 3축, 위반, 판정)
응시 상세 ─ PRD 8장 형식 요약(AI 실무역량 78/100, 3축) ─ 탭: 채점 근거, 대화, 답안 이력, 토큰 원장, 시간 기록
```

## 원칙

- 계기판 한 곳만 대담하게, 나머지는 조용하게.
- 색은 의미로만 쓴다. 장식 그라데이션, 그림자 카드, 대문자 라벨, 화살표 버튼 없음.
- 사용자가 일으키지 않은 움직임은 공지 등장 하나뿐이다. reduced motion이면 그것도 끈다.
- 키보드만으로 모든 조작이 된다. 포커스 링은 `--action` 2px.
- 모의 AI·모의 채점일 때는 화면에 그 사실을 늘 표시한다(결정: AI 모의 게이트웨이).

## 변경 (2026-09-27 신영환 요청)

- 응시 화면 가운데 칸을 Case 하나의 한 페이지 문서로 바꿨다. 과제 설명, 받은 공지, 문항마다 [지시문, 답안 조건, 유의사항, 답안]이 위에서 아래로 이어진다. 왼쪽 목록은 누르면 그 문항으로 스크롤하는 목차이고, 화면 위쪽 35% 선을 마지막으로 지난 문항을 '지금 보는 문항'으로 표시한다(문항별 시간 기록과 AI 대화의 문항 표시도 이것을 따른다). 이유: 페이지 전체를 AI에 그대로 붙여 넣는 행동이 드러나게 하려는 것.
- 답안마다 '임시 저장' 버튼을 '최종 제출' 옆에 두었다(자동저장은 그대로).
- 선택형 문항에 자유 기술 칸(패키지의 `answer.note`)을 둘 수 있다. 샘플 1-1에 '비고(선택 근거)'를 켰다.
- 문항별 유의사항(패키지의 `guidance`)을 문항 아래에 보여 준다.
- 자료 첨부 창에 '열 모두 선택'을 추가했다.
- 샘플 1-2 지시문이 뒤 문항(1-3)을 가리키던 것을 고쳤다.
