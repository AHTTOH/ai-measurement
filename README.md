# AI 실무역량 평가 플랫폼

> 최초 작성: 2026-09-27 · 마지막 갱신: 2026-09-27
> 구조 규칙이 바뀔 때만 '마지막 갱신'을 그날 절대 날짜로 고친다.

제한된 시간과 AI 사용량 안에서 실무 과제를 수행하게 하여, 판단·AI 활용·결과물 세 축으로 AI 실무역량을 평가하는 시험 플랫폼.

## 먼저 읽을 문서

| 문서 | 내용 |
|---|---|
| `docs/PRD.md` | 제품 요구사항 원본 |
| `docs/plan/2026-09-27-prd-구현계획.md` | 구현계획. 결정 필요 항목(0장), 단계(8장), 다음 행동(14장) |
| `docs/decisions/` | 확정된 결정 기록 |
| `docs/runbook/로컬-개발-실행.md` | 설치·실행·검증 명령 |
| `docs/runbook/시험-운영-절차.md` | 시험 전·당일·종료 후 운영과 장애 대응 |
| `docs/runbook/API-키-연동-절차.md` | Claude API 키를 받은 뒤 연동·검증 순서 |
| `docs/audit/` | 검증 보고서 |

진행 상태는 이 문서에 적지 않는다. 구현계획 8장 진행 현황과 14장 다음 행동이 원본이다.

## 디렉토리 구조 (2026-09-27 승인)

```
ai-measurement/
├── README.md       # 이 문서. 구조의 원본
├── docs/           # PRD, 구현계획, 결정 기록, 점검 리포트, 운영 절차
├── exams/          # 시험 패키지(데이터). 실제 시험은 커밋 금지, 샘플만
├── server/         # API 서버: 인증·세션·타이머·AI 프록시·토큰 원장·답안·감사 로그
├── web/            # 프론트: 응시자 화면, 관리자 화면
├── grading/        # 자동채점: 규칙·LLM·집계. 서버 없이 실행 가능
├── shared/         # 공통 스키마·타입·설정 항목 형식. 값은 두지 않는다
├── infra/          # DB 스키마·마이그레이션·배포 설정·.env.example
├── scripts/        # 운영 스크립트: 패키지 검증, 응시자 등록, 재채점, 부하 테스트
├── tests/          # 단위·통합·e2e·부하 테스트
└── workspace/      # 임시 산출물(커밋 제외)
```

각 폴더의 용도와 규칙은 그 폴더의 `README.md`가 원본이다. 하위 파일 목록은 문서에 베끼지 않는다. 목록은 `ls`로 확인한다.

## 구조 규칙

- 최상위 폴더의 추가·삭제·이름 변경, 폴더 간 이동은 신영환 승인 후에만 한다. 승인 내용은 `docs/decisions/`에 날짜 파일로 남긴다.
- 파일 이름만 보고 정체를 알 수 있게 짓는다. `data.json`, `utils` 같은 모호한 이름은 쓰지 않는다.
- 임시 파일은 `workspace/` 아래에만 만든다. 루트에 흩뿌리지 않는다.
- 설정값(모델 ID, 토큰 예산, 시험 시간, 배점 등)은 코드에 직접 쓰지 않는다. 시험 패키지와 환경 설정에서 읽는다.
- 값이 비어 있거나 없으면 기본값으로 메우지 않는다. 드러내고 원인을 고친다.
- `server/`·`web/`·`grading/`의 내부 구조는 기술 스택(구현계획 D1) 확정 후 정한다.
